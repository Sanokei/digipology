# Next observed card-art gap after the cover/default-back pipeline

This is an audit/next acceptance plan, not an implemented feature or approved artwork.

The human requires art created for each game and actual cards/decks/dice, rather than primitives or sample covers. The current normal creation path has game-authored direction and separate raster cover/default-back jobs, with one default back explicitly disclosed for multi-deck games. Its actual provider remains unconfigured; technical raster fixtures are not accepted final art.

Actual wiring: apps/worker/src/ai-games.ts authors definitions with only id/label/color. apps/web/src/scene/pieceArtwork.ts reduces nonstandard cards to custom-card label/accent; pieceArtworkCanvas.ts renders that generic text ornament. cardBackForGame() selects one game-wide presentation image. These contracts cannot represent the source's distinct Spell/Potion/Tea Leaves/Crystal Ball fields or a deliberate back for each deck. The seven real Sheets now contain88 named definitions (8 golems,4 guards,12 Tea Leaves,26 Crystal Ball,17 spells including a zero-copy entry,7 potions,14 decrees), plus count/trigger ambiguities; those are sources, not88 implemented/generated cards.

The next bounded usable slice should make front metadata and deck back bindings explicit in versioned presentation files outside canonical state, feeding the same table/hand/inspection painter. Use actual source fields (name, cost/ingredients, activation/condition, ability, flavor where present) and a separate raster illustration. Never invent a card effect from a random picture, truncate authoritative rules silently, map assets by guessed game title, or pass an unrevealed face's metadata into its back painter. The standard named52-card identity path and existing releases must stay exact.

Alternatives to critique before coding: per-definition art assets vs deliberate shared illustrations per card family; public deck-type binding vs renderer inference from current container; retained summary/full-rules presentation vs tiny unreadable text. Dynamic cards/moves must keep their intended printed back without consulting another seat's hidden action history. Artwork job budgets/rates must be considered before promising one-prompt completion for a large catalog; current per-image cover/back jobs do not establish that scale.

Acceptance for one complete slice: two actual card families with distinct back bindings and rich readable fronts through ordinary generated/imported draft metadata, editor, private play, owner/guest hand and inspection, saved-file round trip, publication/download/reload. Verify actual font wrapping/long effects on desktop and390px, physical mask/corners, correct illustration source/purpose/hash/credits, failed-image retry preserving prior art and gameplay, and no hidden face/name/cost/illustration in another seat's inspection or accessible headings. Prepared provider-port fixtures can verify transport only. Genuine live art/theme coherence and perceptual style need actual authorized provider output and review; do not call local fixture pixels or test counts one-shot greatness.

No new showcase batch, media type, provider secret/purchase, automation copy or deployment is proposed by this audit. Full faithful Merlin generation-to-play/repair, resolving the recorded source gaps, performance at its full catalog size and real fun/sound review remain later acceptance work.
