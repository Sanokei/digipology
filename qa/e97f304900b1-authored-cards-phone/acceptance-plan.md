## Alternatives and chosen slice

1. Whole raster card faces vs structured printed fields plus illustrations. Choose structured card fields painted consistently in table/hand/inspection with a separate real raster illustration. This keeps text editable/readable and full long rules accessible; never rely on a generated image to reproduce game text. Preserve existing named52-card faces when no explicit design overrides them.
2. Guessing family from title/current container vs authored stable bindings. Choose explicit definitionId→familyId and deck fallback bindings to actual authored entities. A moved card keeps its family. A deck's top printed back follows its actual top card's public back binding when available; an empty deck uses its authored fallback. No unrevealed face/name/cost/illustration reaches the back painter or another viewer's headings.
3. One expensive image per definition vs intentional family art with individual overrides. Choose a game-authored family illustration/back plus optional individual card illustrations. This permits coherent families without requiring88 new images for Merlin. The game chooses its names, printed fields, palette and image briefs; there is no hard-coded visual game theme or new fixture-art library. Automatic work is serial/bounded and exposes provider/rate failures; no large-catalog one-shot/billing guarantee is claimed.
4. Remote mutable URLs vs self-contained versioned assets. Choose runtime/presentation/cards.json version1 with bounded embedded PNG/JPEG/WebP, hashes/dimensions/credits/provenance and explicit references. It is part of release-file integrity but outside canonical game state. Private job/original locators stay in editor-only generation metadata; old releases and cover versions remain exact. Keep the1MiB release budget and reject attachment atomically rather than dropping art. A future large external media index is separate work.
5. Tiny text to fit vs full accessible rules. Use measured wrapping and a readable minimum type size. If full effect text exceeds the physical card area, show an explicit full-rules-in-inspection marker; keep the full untruncated text in the inspector and saved file. No hidden silent truncation or fabricated mechanics.

## Proposed surface

Strict versioned card-design file: family IDs/names/accent palette, family back/default-illustration asset references, explicit card definition bindings with title/type/cost-or-ingredients/condition/effect/flavor and optional illustration reference, plus explicit fallback deck bindings and a deduplicated bounded image table. Validate bindings against actual card/deck definitions/entities, duplicates, unsupported/executable/remote media, malformed dimensions, bytes and SHA256. Metadata can exist with deliberately pending optional images; a supplied broken image is a repair/publication barrier, never a fake-ready asset.

Normal AI authoring emits the printed metadata and game-specific family/individual briefs. Assembly splits public presentation from private generation jobs and preserves exact selected prior images on edit by stable targets. Existing cover/default-back receipts and legacy bundles remain compatible. Scoped family-back/family-illustration/card-illustration generation uses the existing authorized image adapter with correct purpose/cache identity and retained originals, never a sample cover substitution. Missing live credentials remain a truthful503/unconfigured state.

Normal Artwork gains Cards & decks editing, actual-card/family selection and preview, full text/credits, scoped image upload/create/retry/original/download controls, and an editable backup after quota failure. Changes update presentation in an active private playtest without restarting gameplay, make earlier release review stale and survive normal desktop editor/publication/download/reload. Changing printed text does not secretly change Lua rules; the author receives clear feedback about that distinction.
