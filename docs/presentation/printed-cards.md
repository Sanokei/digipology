# Printed cards and per-family artwork

Custom cards can carry editable printed fields and raster illustrations, with explicit family backs. This presentation stays outside deterministic game state. Existing standard52-card faces and old releases keep their original rendering unless an author explicitly supplies a design.

`runtime/presentation/cards.json` is a version1 `digipology-card-designs` release file. `families` contain stable IDs, names, ink colors, an optional illustrated-front choice and selected back/default-illustration asset references. `cards` bind actual definition IDs to a family and retain the complete title, type, cost/ingredients, activation condition, effect, flavor and up to eight additional fields. Optional per-card illustrations override the family image. Zero-copy authored definitions are valid. `decks` bind real deck entities to an empty-deck fallback family. `assets` embed hashed PNG/JPEG/WebP bytes, dimensions, artist/license/source credits and retained original hash/dimensions/preparation recipe when available. Local filenames, private input documents, private generation briefs and owner-only original locators never enter this file.

Bindings are authored, not guessed from a title or a card's current container. Moving a card does not change its family. A physical deck shows the family back of its actual last/top card; an empty deck uses its explicit fallback. Unknown cards retain the neutral/default game back. Concealed painters and inspection receive only public family-back data. Owner hands and revealed faces use one shared raster painter across Core, native Lite and DOM inspection. Printed fields wrap using actual font metrics; overflowing physical cards explicitly direct the player to full, untruncated, keyboard-scrollable inspection. These are presentation privacy boundaries, not cryptographic hidden-state secrecy.

Normal Artwork → Cards & decks edits the actual draft's families, bindings, printed fields, shared illustrations and individual overrides. Uploads pass real browser decoding, orientation, crop/contain, opaque cream matte and WebP preparation. Scoped backs are512×768; illustrations768×512; cover/default-back preparation remains unchanged. Each scoped image is at most256KiB, the card-design file at most850KiB, and the complete upload remains within1MiB. Attachment is atomic. Credits and original/processed hashes survive normal editor editing, private play, release download, publication/reload and editable backup. A failed save retains in-tab pixels and offers an editable download and retry. A supplied damaged image blocks publication. An integrity-valid private backup remains playable with safe paper while the author deliberately replaces/removes damaged art; release file/hash corruption is not silently repaired.

Native game authoring can emit `cardDesigns` version1 with family/definition/deck structures and private image briefs. Assembly validates actual bindings, splits private work from public printed data, and preserves selected prior images by stable targets. The existing artwork controller serializes cover/default-back/scoped jobs. Shared family art avoids requiring one image for every definition; individual briefs opt into extra images. Scoped provider requests include family/card identity and brief in the owner/draft/purpose/revision cache key. Illustrations request genuine landscape1536×1024 output, backs portrait1024×1536. Successful originals are retained in owner-only storage before acknowledgement. Decode/budget/storage failures preserve the prior selection, attempted original and prepared output; retry reuses completed work. Fully bound card plans do not generate a redundant game-wide default back. There is a64-scoped-job bound and the existing account rate/daily limits; a large catalog is not an unlimited image-generation promise.

A game without live configured text/image access still reports the existing unconfigured failures and supports authored/imported/manual draft work. The technical browser ports use the existing First Deal rules and existing authorized raster inputs (including a real FFmpeg landscape crop) to exercise processing and integration. They are not genuine model output, approved final art, full faithful Merlin Economics, perceptual sound review or proof of fun. The user's seven original Sheets and full copyrighted rulebook remain private. Their source/count/rule gaps are recorded separately. The pre-existing unpublished AI-edit prompt-size limitation is also separate: placing a large embedded bundle into an8k prompt is not a complete editing solution.

Renderer loading uses the existing eight-second budget per attempt, including module import, GPU acquisition, scene/shader assets and first frame. Each attempt owns a separate canvas. Timeout, fallback, navigation and view retry invalidate ownership, dispose current resources and positively retire late engines/scenes. A late import cannot mount. Reload table view retries presentation in place: the room client, private hand, draft and editor undo store remain mounted. If Chromium retains a failed renderer entry fetch, retry may request that same origin's exact hashed entry with a fresh URL; it never imports arbitrary URLs or rewrites source. Unknown dependency errors remain visible. Existing failed native shared-process software-GPU evidence remains a performance limitation; successful separate-browser native validation does not close it.
